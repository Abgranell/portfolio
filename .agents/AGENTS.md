
# Portfolio Project — Shared Instructions

## 1. Project objective

Upgrade and improve the existing professional portfolio of Arnau Boix Granell.

The portfolio presents his professional career, engineering experience, robotics research, technical projects, publications and achievements.

The objective is to improve the existing website, not replace it with an entirely new implementation.

## 2. Existing website

The project already contains a functional website.

Public website:
https://abgranell.github.io/portfolio/

GitHub repository:
https://github.com/Abgranell/portfolio

The existing implementation is based on HTML and CSS and includes:

- index.html: Landing page and language selection.
- cat/: Catalan website.
- eng/: English website.
- css/: Stylesheets.
- giff/: GIF demonstrations and animations.
- imatges/: Images and other visual resources.

The English website already includes:

- About me
- Professional Experience
- Education
- Academic Projects
- Professional Projects
- Articles & Publications
- Other

The Catalan version must also be maintained.

These descriptions are an initial reference. Always inspect the actual workspace to establish the current structure and contents.

## 3. Mandatory initial inspection

Before proposing or implementing any changes:

1. Inspect the complete repository structure.
2. Read all relevant HTML and CSS files.
3. Identify shared styles and dependencies.
4. Inspect existing images, GIFs and other assets.
5. Understand the navigation between pages.
6. Identify duplicated content between Catalan and English.
7. Understand how the website is deployed through GitHub Pages.
8. Identify existing design patterns and reusable components.

Produce an initial audit before modifying anything.

Never assume that the public website or the initial description contains all the latest source code.

## 4. Preservation rules

- Preserve the existing website architecture whenever possible.
- Do not migrate to React, Next.js, Vue or another framework without explicit approval.
- Do not replace the website with a new template.
- Do not delete existing pages, images, GIFs or content without approval.
- Preserve all existing links and navigation functionality.
- Preserve both Catalan and English versions.
- Preserve existing project descriptions unless improvements are justified.
- Reuse existing visual assets whenever appropriate.
- Avoid unnecessary dependencies.

## 5. Content accuracy

Never invent:

- Projects or professional experiences.
- Technical responsibilities.
- Publications or awards.
- Performance metrics.
- Personal contributions.
- Results or achievements.

Distinguish between individual contributions and collaborative project results.

If information is missing, ask Arnau or flag it for verification.

## 6. Modification strategy

Before substantial modifications:

1. Explain the problem.
2. Propose the improvement.
3. Identify the affected files.
4. Explain possible consequences.
5. Obtain approval when the change is substantial.

Prefer incremental improvements over complete rewrites.

Keep changes organized and reversible through Git.

## 7. Bilingual consistency

Every relevant content improvement must be considered in both English and Catalan.

Maintain equivalent meaning, technical accuracy and professional tone.

Do not allow the two language versions to become inconsistent.

## 8. Quality requirements

The final website should be:

- Technically credible.
- Visually professional.
- Responsive.
- Accessible.
- Easy to navigate.
- Consistent in both languages.
- Compatible with GitHub Pages.

All links, images, GIFs and navigation elements must be tested.

## 9. Collaboration

Agents must communicate their findings and recommendations to the orchestrator and relevant peer agents.

Avoid duplicated work and conflicting modifications.

The Career Auditor establishes the factual source of truth.

The Robotics Technical Editor validates technical descriptions.

The Portfolio Strategist defines content priorities.

The Storytelling Agent improves communication.

The UX/UI Designer handles visual implementation.

The Recruiter & QA Reviewer independently evaluates the result.

The orchestrator coordinates the entire process.
